# 上位銘柄の含み益検証・住所精度改善手順

`parallel_resolve_address.ps1` から `$resolve-all-address <証券コード> <パッチファイル>` の形式で呼び出される。
指定された企業の全事業所を検証し、番地レベル住所を**必ずパッチファイルに書き出す**。

## 引数

| 位置 | 内容 | 例 |
|------|------|-----|
| 1 | 証券コード | `9351` |
| 2 | パッチファイルパス | `config/address_patches/9351.yaml` |

> **重要**: 調査結果は**必ず**パッチファイルに書き出すこと。`address_overrides.yaml` は直接編集しない。ファイルが書き出されなければリサーチ結果が失われる。

---

## 1. 目的

指定企業について、推定土地時価が正当かを検証し、全事業所の住所を番地レベルで特定してパッチファイルに登録する。

### よくあるパターン（過大評価の原因）

- **複数拠点の合算:** 事業所名が「本社他」「本社及び工場」等で、複数箇所の土地面積が1行に合算されている
  - 全面積が高地価地点（港区・千代田区等）に紐づくが、実際は一部の土地が郊外にある
  - 例: 「本社他 27,000m²」→ 本社は港区（5,000m²）、倉庫は大田区城南島（22,000m²）
- **面積と立地の不整合:** 都心で1万m²超の土地は不自然（工場・倉庫なら工業地帯が妥当）
- **住所精度が低い:** `muni_centroid` / `oaza_chome` で高地価地点の地価が適用されている

## 2. 対象事業所の抽出と分析

`data/output/{証券コード}_output.csv` を読み込み、**全行**を確認する。

```bash
cat data/output/9351_output.csv
```

各事業所について以下の観点でフラグを立てる：

| フラグ | 条件 | 意味 |
|--------|------|------|
| 合算疑い | 事業所名に「他」「及び」「等」を含む | 複数拠点が1行に合算されている |
| 面積異常 | 都心住所なのに面積 ≥ 10,000m² | 立地と面積が不整合 |
| 低解像度 | 住所解決レベルが `muni_centroid` or `oaza_chome` | 番地特定で精度向上の余地あり |

## 3. Web調査の手順

### ステップ1: 有価証券報告書の原文確認

```
検索: "{企業名} 有価証券報告書 設備の状況"
```

EDINETで原本PDFの**設備の状況**テーブルを直接確認:

- 事業所名に「他」「及び」が含まれていないか（複数拠点の合算サイン）
- 注記欄に「上記には○○を含む」等の記載がないか
- 面積の内訳が脚注に書かれていないか

### ステップ2: 企業公式サイトで拠点一覧を特定

```
検索: "{企業名} 拠点一覧"
検索: "{企業名} 事業所 所在地"
検索: "{企業名} 会社概要 アクセス"
```

公式サイトの「会社概要」「拠点紹介」「アクセス」ページで**全拠点の住所を番地レベルで収集**する。

### ステップ3: 個別拠点の住所を番地レベルで特定

```
検索: "{企業名} {拠点名} 住所"
検索: "{企業名} {拠点名} アクセス 地図"
検索: "{企業名} 本店所在地"
検索: "{企業名} 法人番号"  → 国税庁サイトで本店所在地
```

### ステップ4: 面積の妥当性チェック（合算疑いの場合）

```
検索: "{企業名} {拠点名} 工場 敷地面積"
検索: "{企業名} {拠点名} 倉庫 規模"
```

- 工場・倉庫の敷地面積がプレスリリースや IR 資料に載っていることがある
- 「本社他」の合計面積から各拠点の概算面積を逆算する
- 都心で大面積 → 実際にそんな広い土地があり得るか検証

### 3.5 住所の検証

取得した住所が正しいか、以下の観点で検証する：

1. **区市町村の一致** — 有報の住所と同じ区市町村か
2. **事業所名との整合性** — 工場なら工業地帯、本社なら商業地域にあるか
3. **番地の具体性** — 「○丁目○番○号」または「○-○-○」まで特定できているか
4. **複数ソースでの裏付け** — 2つ以上の情報源で同じ住所が確認できるか

### 3.6 住所の正規化

パッチファイルに登録する前に、住所を以下の形式に正規化する：

```
東京都{区市町村}{町名}{丁目}{番}{号}
```

- 全角数字 → 半角数字（例：「３丁目」→「3丁目」）
- 漢数字 → アラビア数字（例：「三丁目」→「3丁目」）
- ハイフン形式も可（例：「東京都港区六本木3-4-33」）
- 郵便番号は含めない
- ビル名・階数は含めない（土地のジオコーディングには不要）
- 「東京都」から始めること

**良い例:**
```
東京都中央区日本橋1丁目15番3号
東京都港区六本木3-4-33
東京都足立区千住橋戸町31番
```

**悪い例:**
```
中央区日本橋1-15-3          # 「東京都」が無い
東京都中央区日本橋           # 番地が無い（oaza_chomeにしかならない）
〒100-0001 東京都千代田区... # 郵便番号が含まれている
東京都港区六本木ヒルズ       # ビル名で番地が無い
```

## 4. 判定

検証結果に基づき、各事業所について以下のいずれかに判定する：

| 判定 | 説明 | アクション |
|------|------|-----------|
| **住所改善** | 番地レベル住所を特定できた | → セクション5でYAML登録 |
| **確認済み** | 既に `gaiku` で住所も正確 | → 現住所をそのままYAML登録 |
| **過大評価の疑い** | 合算・面積不整合が確認された | → 代表住所をYAML登録 |

> **重要**: 判定結果に関わらず、**全事業所の住所を必ずパッチファイルに登録する**。

### 判定フローチャート

```
対象企業の全事業所を確認
  │
  ├─ 事業所名に「他」「及び」→ 合算の疑い
  │   └─ 原本PDF確認 → 拠点分解 → 代表住所をYAML登録
  │
  ├─ 面積≥10,000m² かつ都心住所 → 立地の妥当性確認
  │   └─ 正しい住所をYAML登録
  │
  ├─ 住所解決レベルが muni_centroid / oaza_chome → 番地特定
  │   └─ 番地付き住所をYAML登録
  │
  └─ 上記に該当しない → 現在の住所をそのままYAML登録
```

## 5. パッチファイルへの書き出し

**このセクションは必ず実行する。** 調査結果はパッチファイルに書き出さなければ失われる。

### 5.1 ジオコード検証

登録する住所が `gaiku` レベルでジオコーディングできるか確認する：

```python
from src.geocode_tokyo import TokyoGeocoder

geocoder = TokyoGeocoder(
    oaza_csv="data/geocoding/geocode_ref_oaza_chome_tokyo_2024/13_2024.csv",
    gaiku_csv="data/geocoding/geocode_ref_gaiku_tokyo_2024/13_2024.csv",
)

addr = "東京都足立区宮城1丁目35番18号"
lat, lon, level = geocoder.geocode(addr)
print(f"{addr} → {level} ({lat}, {lon})")
# 期待: "gaiku" と表示されること
```

- `gaiku` が得られればベスト（補正係数 1.00）
- `oaza_chome` でも `muni_centroid` からの改善になる（補正係数 0.85 → 0.95）
- `muni_centroid` のままなら住所が不正確な可能性 → 再調査

**全住所のジオコード結果を確認してからパッチファイルに書き出すこと。**

### 5.2 ファイル構造

引数で指定されたパッチファイル（例: `config/address_patches/9351.yaml`）に以下の形式で**新規作成**する：

```yaml
'9351':
  本社: 東京都中央区日本橋2丁目7番1号
  東京支店: 東京都江東区有明4丁目3番22号
```

### 5.3 登録ルール

- **事業所名は出力CSVの値と完全一致させる**（スペース含む）
  - 例: 出力CSVが「本社 他」なら、YAMLのキーも `本社 他` にする
  - 例: 出力CSVが「本社他」なら `本社他` にする
- **証券コードはクォート付き文字列として記載**（`'1234':` の形式）
- **対象企業の全事業所を登録する**（低解像度でない事業所も含む）

### 5.4 書き出し後の確認

パッチファイルに書き出したら、内容を `cat` で表示して正しく書き出されたことを確認する：

```bash
cat config/address_patches/9351.yaml
```

## 6. 注意事項

- **集約名の事業所**（「本社他」「本社・○○」「○○等」）は、複数の土地が1行に集約されている。代表的な住所（通常は本社住所）を設定する。
- **移転情報に注意** — 検索で見つかる住所が最新でない場合がある。有報の事業年度末時点の住所であることを確認する。
- **ジオコーディング参照データの範囲** — `data/geocoding/` の参照CSVは東京都2024年版。参照データに存在しない新しい街区番号の場合、番地付きでも `oaza_chome` にフォールバックする。この場合は改善の余地がない。
